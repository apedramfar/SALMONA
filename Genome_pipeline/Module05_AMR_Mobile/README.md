# Module 05 — Mobile Elements & Antimicrobial Resistance

## Overview

This module screens bacterial genome assemblies for antimicrobial resistance (AMR) determinants, virulence-associated genes, stress response genes, and putative plasmid sequences using **AMRFinderPlus**, **geNomad**, and **ResFinder**.

The module operates independently of Module03_Annotation and uses genome assemblies generated by Module02_Assembly. Each analysis can be enabled or disabled through `config.sh`, allowing individual tools or combinations of tools to be executed.

Results from the enabled analyses are aggregated into per-tool summary tables and a combined sample-level report for downstream comparative genomic analyses.

Prophage detection and characterisation are handled separately in Module06_Prophages.

## Input Files

The module requires a tab-separated sample sheet and assembled genome FASTA files from Module02_Assembly.

### 1. Sample sheet

The sample sheet contains three tab-separated columns:

```text
sample_id	read1	read2
isolate_01	/path/to/isolate_01_R1.fastq.gz	/path/to/isolate_01_R2.fastq.gz
isolate_02	/path/to/isolate_02_R1.fastq.gz	/path/to/isolate_02_R2.fastq.gz
```

The read paths are retained for consistency with earlier pipeline modules. Module05 uses the sample identifiers to locate assembled genome files.

### 2. Genome assemblies

Expected input files:

```text
output_dir/
└── 02_assembly/
    └── fasta/
        ├── isolate_01.fasta
        └── isolate_02.fasta
```

Each assembly filename must correspond to a sample identifier in the sample sheet.

The runner checks whether the required assembly files exist before submitting analysis jobs.

## Configuration

Copy the provided example configuration:

```bash
cp config.example.sh config.sh
```

Edit `config.sh` to specify the sample sheet, output directory, and SLURM log directory:

```bash
SAMPLE_SHEET="/path/to/samples.tsv"
OUT_DIR="/path/to/output"
LOG_DIR="/path/to/logs"
```

### Enable or disable analyses

```bash
RUN_AMRFINDER=true
RUN_GENOMAD=true
RUN_RESFINDER=true
```

Set a switch to `false` to disable the corresponding analysis. At least one analysis must be enabled.

### AMRFinderPlus configuration

```bash
AMRFINDER_ORGANISM="Salmonella"
AMRFINDER_DB="/path/to/amrfinderplus/database"
```

The organism setting can be changed to another supported organism or set to `mixed` to omit the organism-specific flag.

Available organism names can be checked using:

```bash
amrfinder --list_organisms
```

### geNomad configuration

```bash
GENOMAD_DB="/path/to/genomad/database"
```

### ResFinder configuration

```bash
RESFINDER_DB="/path/to/resfinder/database"
```

The ResFinder script expects the configured database directory to contain the relevant database subdirectories, including:

```text
resfinder_database/
├── resfinder_db/
├── pointfinder_db/
└── disinfinder_db/
```

ResFinder dependencies must also be available in the execution environment.

### Software packages

```bash
PKG_AMRFINDER="your_amrfinder_package"
PKG_GENOMAD="your_genomad_package"
PKG_RESFINDER="your_resfinder_package"
```

The supplied scripts use `source package` to load software on the original HPC environment. Package identifiers and loading commands may require adaptation on other systems.

### SLURM configuration

Configure partition names, CPU allocation, memory, and maximum runtime for each analysis.

The example configuration includes separate resource settings for AMRFinderPlus, geNomad, ResFinder, and the merge job.

The local `config.sh` file is excluded from Git version control. Only `config.example.sh` is intended for publication.

## How to Run

### 1. Confirm Module02 has completed

Ensure the required genome assemblies are present under:

```text
$OUT_DIR/02_assembly/fasta/
```

### 2. Launch Module05

From the `Module05_AMR_Mobile` directory:

```bash
bash 05_run_mobile_amr.sh
```

The script checks the sample sheet, verifies that assembly files exist, and submits SLURM job arrays for the enabled analyses.

### 3. Workflow structure

```text
05_run_mobile_amr.sh
         |
         ├── 05a_amrfinder.sh  ──┐
         |                      |
         ├── 05b_genomad.sh    ──┤
         |                      |
         └── 05c_resfinder.sh  ──┤
                                |
                                ▼
                          05d_merge.sh
                                |
                                ▼
                    mobile_amr_summary.tsv
```

Each enabled analysis runs as a separate SLURM array, with one task per sample.

The merge job uses an `afterok` dependency and is scheduled after successful completion of all enabled analysis arrays.

If an analysis is disabled, its array is not submitted and its result columns are omitted from the combined summary.

### 4. Monitor running jobs

```bash
squeue -u "$USER"
```

SLURM output and error logs are written to `LOG_DIR`.

### 5. Check the results

After the analyses and merge job have completed:

```bash
bash 05_check_mobile_amr.sh
```

The checker verifies expected per-sample and aggregated files and reports summary statistics for the enabled analyses.

## Output Descriptions

### AMRFinderPlus — `amrfinder_summary.tsv`

| Column | Description |
|---|---|
| `sample_id` | Sample identifier |
| `amr_genes` | Number of AMR-classified findings |
| `virulence_genes` | Number of virulence-classified findings |
| `stress_genes` | Number of stress-classified findings |
| `total_findings` | Total number of reported findings |
| `amr_classes` | Semicolon-separated list of reported AMR classes |

The summary is generated from the AMRFinderPlus tabular output.

The current merge script uses fixed column positions to identify finding categories and AMR classes. These positions should be verified against the output header of the installed AMRFinderPlus version.

### geNomad — `genomad_summary.tsv`

| Column | Description |
|---|---|
| `sample_id` | Sample identifier |
| `plasmid_count` | Number of predicted plasmid sequences |
| `total_plasmid_length_bp` | Sum of predicted plasmid sequence lengths in base pairs |

The summary is calculated from the geNomad plasmid summary files.

### ResFinder — `resfinder_summary.tsv`

| Column | Description |
|---|---|
| `sample_id` | Sample identifier |
| `resfinder_genes` | Number of reported acquired AMR findings |
| `resfinder_classes` | Semicolon-separated list of reported resistance classes |
| `resfinder_gene_list` | Semicolon-separated list of detected gene names |

The current merge script extracts gene names from the first column and resistance classes from the final column of `ResFinder_results_tab.txt`. These assumptions should be checked against the output format of the installed ResFinder version.

### Combined summary — `mobile_amr_summary.tsv`

The combined table contains one row per sample and includes selected results from all enabled analyses.

Columns are included conditionally according to the configuration switches:

- AMRFinderPlus: AMR, virulence and stress finding counts, and reported AMR classes.
- geNomad: predicted plasmid count and total plasmid length.
- ResFinder: acquired AMR finding counts, resistance classes and detected gene names.

This file provides a starting point for downstream comparative analysis.

## Possible Warnings

The checking script reports missing or empty output files for each enabled analysis.

| Warning | Description |
|---|---|
| `MISSING` — AMRFinderPlus | Expected per-sample AMRFinderPlus TSV file was not found |
| `EMPTY` — AMRFinderPlus | Expected AMRFinderPlus TSV file exists but is empty |
| `MISSING` — geNomad | Expected plasmid summary file was not found |
| `EMPTY` — geNomad | Expected plasmid summary file exists but is empty |
| `MISSING` — ResFinder | Expected `ResFinder_results_tab.txt` was not found |
| `EMPTY` — ResFinder | Expected result file exists but is empty |
| `MISSING` — aggregated output | One or more expected merged or summary files were not generated |
| `EMPTY` — aggregated output | An expected aggregated file exists but is empty |

### Interpretation of warnings

- Missing files may indicate failed SLURM jobs, incomplete execution, or unexpected output paths.
- Empty files may indicate unsuccessful result generation.
- The merge job may remain pending or fail to run if an upstream job array does not complete successfully.
- Missing results are generally represented as `NA` in the relevant per-tool summaries when those summaries are generated.
- Files that exist and are non-empty are considered present by the checker, but this does not establish biological validity or guarantee that every analysis completed correctly.

When warnings are reported, inspect the corresponding SLURM logs and tool-generated outputs before interpreting the combined results.

## Notes on Tool Behaviour and Interpretation

### AMRFinderPlus

AMRFinderPlus is executed on assembled nucleotide sequences using the `--plus` option.

The workflow reports AMR-associated, virulence-associated and stress-associated findings. When a supported organism is specified, applicable organism-specific detection rules may be used.

When `AMRFINDER_ORGANISM="mixed"`, the script omits the organism flag.

Detected genetic determinants should not be interpreted as direct evidence of phenotypic antimicrobial resistance without appropriate supporting evidence.

### geNomad

geNomad is run using its `end-to-end` workflow with:

```bash
--disable-find-proviruses
--cleanup
```

The `--disable-find-proviruses` option disables the integrated provirus identification step. It does not restrict geNomad exclusively to plasmid classification.

For this module, only the plasmid-related summary files are aggregated.

Predicted plasmid sequences are computational classifications and should not automatically be interpreted as experimentally confirmed extrachromosomal plasmids.

### ResFinder

ResFinder is used to identify acquired antimicrobial resistance determinants from genome assemblies.

The current script uses:

```bash
-l 0.6
-t 0.8
--acquired
```

These specify a minimum sequence coverage threshold of 60%, an identity threshold of 80%, and acquired resistance gene analysis.

ResFinder complements AMRFinderPlus, but differences in database content, thresholds and detection strategies may lead to different results for the same isolate.

The script does not perform a separate PointFinder mutation analysis.

### Reproducibility

For reproducible analyses, record:

- Software and database versions.
- Sample sheet and assembly identifiers.
- Configuration switches and organism settings.
- Detection thresholds and software parameters.
- SLURM job completion status.
- Any manual review or filtering of predicted findings.

The repository provides the scripts and example configuration, but does not include the external reference databases or original research datasets.
