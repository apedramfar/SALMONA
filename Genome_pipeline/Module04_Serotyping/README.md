# Module 04 — Salmonella Serotyping

## Overview

This module performs in silico serotyping of *Salmonella* genome assemblies using **SeqSero2** and **SISTR**. Both tools independently predict Salmonella serovars, and their results are combined into a unified summary table for comparison and downstream genomic analyses.

The workflow is designed for an HPC environment using SLURM job arrays. SeqSero2 and SISTR are submitted independently, allowing multiple samples to be processed in parallel.

---

## Tools and Requirements

| Tool | Version | Purpose |
|---|---|---|
| SeqSero2 | 1.3.2 (as documented in the original workflow; verify installed version) | Salmonella serovar prediction based on antigenic determinants |
| SISTR | 1.0.2 (HPC package tested) | Salmonella serovar prediction and genomic typing |
| Python 3 | Environment-dependent | Parsing SISTR CSV results |
| SLURM | Cluster-dependent | Submission and management of parallel jobs |

The SeqSero2 script uses k-mer mode (`-m k`) with assembled genome FASTA input (`-t 4`).

Software packages and available SLURM partitions must be configured for the user's computing environment.

## Input Files

The module requires a tab-separated sample sheet and assembled genome FASTA files generated by **Module02_Assembly**.

### 1. Sample sheet

The sample sheet must contain three tab-separated columns:

```text
sample_id    read1    read2
isolate_01   /path/to/isolate_01_R1.fastq.gz   /path/to/isolate_01_R2.fastq.gz
isolate_02   /path/to/isolate_02_R1.fastq.gz   /path/to/isolate_02_R2.fastq.gz
```

Although the sample sheet includes sequencing read paths, Module04 uses the sample identifiers to locate assembled genome FASTA files.

### 2. Genome assemblies

The expected input FASTA files are:

```text
output_dir/
└── 02_assembly/
    └── fasta/
        ├── isolate_01.fasta
        └── isolate_02.fasta
```

The filenames must match the sample identifiers in the sample sheet.

## Configuration

Copy the provided example configuration:

```bash
cp config.example.sh config.sh
```

Edit `config.sh` to define the input, output, and logging directories:

```bash
SAMPLE_SHEET="/path/to/samples.tsv"
OUT_DIR="/path/to/output"
LOG_DIR="/path/to/logs"

ASSEMBLY_DIR="$OUT_DIR/02_assembly/fasta"

SEROTYPING_DIR="$OUT_DIR/04_serotyping"
SEQSERO2_DIR="$SEROTYPING_DIR/seqsero2"
SISTR_DIR="$SEROTYPING_DIR/sistr"
```

Configure the required software packages:

```bash
PKG_SEQSERO2="your_seqsero2_package"
PKG_SISTR="your_sistr_package"
```

The scripts use the HPC-specific command `source package` to load software. Package identifiers must match those available on the target cluster.

Adjust the SLURM settings in `config.sh` as appropriate:

```bash
# SeqSero2
PARTITION_SEQSERO2="your_partition"
TIME_SEQSERO2="24:00:00"
CPUS_SEQSERO2=10
MEM_PER_CPU_SEQSERO2="6400M"

# SISTR
PARTITION_SISTR="your_partition"
TIME_SISTR="12:00:00"
CPUS_SISTR=4
MEM_PER_CPU_SISTR="4G"
```

The local `config.sh` is excluded from version control. Only `config.example.sh` is intended for inclusion in the GitHub repository.

## How to Run

### 1. Prepare the input files

Ensure that:

- The sample sheet exists and contains the required columns.
- All expected assembly FASTA files are available in `ASSEMBLY_DIR`.
- The software package identifiers and SLURM settings are configured correctly.

### 2. Launch the serotyping module

From the `Module04_Serotyping` directory, run:

```bash
bash 04_run_serotyping.sh
```

The runner verifies the sample sheet and checks that the required genome assemblies are present before submitting two independent SLURM job arrays:

```text
04_run_serotyping.sh
        |
        ├── 04a_seqsero2.sh
        |       └── SeqSero2 serovar prediction
        |
        └── 04b_sistr.sh
                └── SISTR serovar prediction
```

Each array processes one sample per task.

The two job arrays are submitted independently; the current runner does not specify a SLURM dependency between them.

### 3. Monitor running jobs

```bash
squeue -u "$USER"
```

Check the SLURM output and error logs in `LOG_DIR` if any jobs fail.

### 4. Check serotyping results

After both job arrays have completed, run:

```bash
bash 04_check_serotyping.sh
```

The checker extracts the predicted serovars from SeqSero2 and SISTR and generates a combined summary table.

## Expected Outputs

```text
output_dir/
└── 04_serotyping/
    ├── seqsero2/
    │   ├── isolate_01/
    │   │   └── SeqSero_result.tsv
    │   └── isolate_02/
    │       └── SeqSero_result.tsv
    │
    ├── sistr/
    │   ├── isolate_01/
    │   │   └── isolate_01_sistr.csv
    │   └── isolate_02/
    │       └── isolate_02_sistr.csv
    │
    └── serotyping_summary.tsv
```

### Combined serotyping summary

The `serotyping_summary.tsv` file contains three columns:

| Column | Description |
|---|---|
| `sample_id` | Sample identifier from the input sample sheet |
| `seqsero2_predicted_serovar` | Predicted serovar reported by SeqSero2 |
| `sistr_predicted_serovar` | Predicted serovar reported by SISTR |

When a prediction is unavailable or cannot be extracted, the corresponding value is recorded as `NA`.

## Possible Warnings

The checking script reports warnings when expected serotyping outputs are missing or empty.

| Warning | Description |
|---|---|
| `SeqSero2 output folder missing` | No SeqSero2 output directory was found for the sample. |
| `SeqSero2 folder exists but result missing/empty` | The output directory exists, but `SeqSero_result.tsv` is missing or empty. |
| `SISTR output folder missing` | No SISTR output directory was found for the sample. |
| `SISTR folder exists but result missing/empty` | The output directory exists, but the expected SISTR CSV file is missing or empty. |
| `NA` prediction | A predicted serovar could not be extracted, or an expected result file was unavailable. |

### Interpretation of warnings

- **Missing output directories:** May indicate that a SLURM job was not executed, failed, or wrote results to an unexpected location.
- **Missing or empty result files:** May indicate a software execution problem, incomplete output generation, or incorrect file paths.
- **`NA` predictions:** May reflect missing results or predictions that were not successfully extracted.
- **Discordant predictions:** SeqSero2 and SISTR may report different serovars for the same isolate. Such cases should be examined before downstream interpretation.

Warnings do not stop the checking script. Samples with missing results remain in the combined summary table, with unavailable predictions reported as `NA`.

The current checker does not automatically flag discordant SeqSero2 and SISTR predictions or exclude samples from downstream analyses.

## Additional Notes

- This module requires assembled genomes from Module02_Assembly.
- SeqSero2 and SISTR are executed independently, and both should finish before the combined results are checked.
- The workflow should be launched from the `Module04_Serotyping` directory because the scripts use relative paths to load the configuration and submit the analysis scripts.
- The `References/` directory is excluded from GitHub to avoid distributing large external reference datasets.
- Additional manual reference-analysis scripts are separate from the main Module04 workflow and are not required for its standard execution.
- The successful Bash syntax checks performed during repository preparation do not replace validation of the workflow on the target HPC environment.
